# 5 分钟上手与验收清单（14 条断言）

本文给评审用：装好、启动、按清单逐条手动验证。14 条断言里第 1、2、3、5、7、8、9、10、12 条不需要 API Key；第 13 条的展示与规则层也不用 Key，模型层那一步配 Key 更直观；第 4 条需要先配一把有效 Key 存下技能，再故意把 Key 改错；第 6 条的偏好抽取与落盘不依赖模型，但「回复变短」这类措辞变化在配 Key 后更直观；第 11 条需要启动 API 服务，但不需要 Key；第 14 条（本地微调模型）不配 Key 也能验，只在装了 `requirements-finetune.txt` 并训出适配器时才能看到完整链路。

命令与口径与 [README.md](../README.md) 一致：项目名「凌零 · 桌面 AI 数字员工」，仓库 github.com/hm-yep/L-Agent。

## 准备

```bash
pip install -r requirements.txt
```

无 Key 启动（Windows / Linux 相同，桌面版默认 `USE_REAL_AI=False`）：

```bash
python main.py
```

需要真实模型时再配 Key，Key 只写在本机环境变量或启动后的设置界面里，不进仓库：

```bash
# Windows (CMD)
set DEEPSEEK_API_KEY=你的Key
python main.py

# Linux / macOS
export DEEPSEEK_API_KEY=你的Key
python main.py
```

验证过程中产生的待办、记忆、技能、交付都落在 `data/` 下的本地 JSON 与文件里，该目录已被 `.gitignore` 排除，可随时清理。

## 验证清单

### 断言 1：无 Key 也能执行工具动作（离线规则兜底）

**操作**

1. 确认环境变量 `DEEPSEEK_API_KEY` 未设置，执行 `python main.py`。
2. 等骑士窗口出现，在输入条说「加个待办：交周报」。
3. 右键打开「我的待办」面板。

**预期现象**

- 待办列表里出现「交周报」，气泡有回应；
- 全程没有真实模型调用（离线规则引擎响应工具意图），闲聊类输入给兜底回复。

### 断言 2：撤销真的把世界改回去，并自证

**操作**

1. 接着断言 1，说「撤销」。
2. 重新打开「我的待办」面板。

**预期现象**

- 「交周报」从待办列表消失；
- 气泡按「退回 N 项 / 没撤成 M 项」口径回报（本例为退回 1 项、没撤成 0 项），明细里标成 `[可撤]`，而不是只说一句「已撤销」；
- 这是每轮开工拍世界快照、收口求差集、按差集下逆操作、撤完再求一次差集自证的结果，见 [ADR 0001](adr/0001-undo-by-world-diff.md)。

### 断言 3：不可逆动作如实说明，不假装全能

**操作**

1. 新开一轮，说「打开计算器」。
2. 等计算器窗口出现后，说「撤销」。

**预期现象**

- 气泡明确说明这一步撤不回，例如「程序我已经帮你打开了，但我不替你关——你窗口里可能有你没存的活儿」；
- 计算器窗口不会被关掉；明细里这一项标成 `[撤不回]`。

### 断言 4：把 Key 改成错的，技能重放照样跑通

> 技能要求一轮内至少 2 个实质动作（`SKILL_MIN_STEPS = 2`），所以先要用一把有效 Key 完成一个多步任务并存下技能；重放阶段才把 Key 改错。

**操作**

1. 配好有效 Key 并启动，完成一个含至少两步的任务，例如说「先加个待办：交周报，再记住：我喜欢深色 PPT」，按计划卡确认执行。
2. 说「存成技能」，气泡应回「学会了：「……」」；说「技能列表」可看到技能名和它需要的槽位。
3. 把 Key 改成明显错误的值：在设置界面改，或 `set DEEPSEEK_API_KEY=invalid` 后重启 `python main.py`，确认真实模型已经不可用。
4. 逐字报出技能名（再说一遍当初那句话）。

**预期现象**

- 技能照样重放：待办 / 记忆按这句话里的新值重新执行；
- 气泡说明「重放「技能名」：N 步，这些步骤直接照当初的动作跑，一步都没再问模型」；
- Key 无效不影响这条路径，因为重放全程不启动 AIWorker。原理与证明手段见 [ADR 0002](adr/0002-skill-replay-zero-llm.md)。

### 断言 5：文档工厂能产出可验收的文件

**操作**

1. 回到无 Key（或任意）状态，说「做个 PPT 介绍凌零」（也可加一句「保存到桌面」直接落盘）。
2. 在弹出的保存位置对话框选好目录，或说「保存到桌面」跳过弹窗。
3. 右键打开「我的交付」面板。

**预期现象**

- 生成一份 `.pptx` 文件并登记进「我的交付」，双击可用系统默认程序打开；
- 无 Key 时内容是离线示例内容，说明文档工厂这条链路不依赖真实模型也能跑通；
- 生成文件不会被误当成用户原有文件被撤销删掉（见 [ADR 0001](adr/0001-undo-by-world-diff.md) 的删文件守卫）。

### 断言 6：偏好自动发现，不用先说「记住」

**操作**

1. 无 Key（或任意）状态启动，直接说「我喜欢深色 PPT」；再说「做个 PPT 介绍凌零」，保存后打开 `.pptx` 看配色。
2. 说「简洁点」，再问一句需要展开说明的问题，对比前后回复长度。
3. 说「以后别联网」，再说「查一下新能源汽车销量」。
4. 打开 `data/preferences.json`，核对里面有没有原话。

**预期现象**

- 第二份 PPT 默认用深色主题；若这一句里又显式指定了样式，仍以当次指定为准；
- 「简洁点」之后回答按简洁口径（配 Key 走真实模型时最直观；偏好条目本身在 `data/preferences.json` 里可核对）；
- 「以后别联网」之后 `web_search` 动作在执行前被跳过，气泡说明按偏好不联网、改用已有资料作答；
- `data/preferences.json` 里只有命中的控制短语与原话哈希，没有「我喜欢深色 PPT」这类原话明文；偏好抽取是纯本地规则，不依赖模型、不需要说「记住」。原理见 [ADR 0003](adr/0003-preference-and-evolution.md)。

### 断言 7：问题驱动进化、事件流时间线与任意轮回滚

**操作**

1. 连续两轮制造同一类失败，例如两次让检索结果与查询零重合、或两次读同一个不存在的路径；每轮收口时会归纳规则，同类证据满 2 条才生成。
2. 第三轮再触发同类动作，观察动作执行前是否被自动调整（换词重搜 / 跳过坏路径 / 执行前确认）。
3. 在仓库根目录跑：

```bash
python tools/trace_view.py --trace data/trajectory.jsonl --out timeline.html
```

打开生成的 `timeline.html`，按轮查看 `failure` / `quality` / `rule` 事件、哈希链与「只看失败」过滤。
4. 做几轮会改动世界的动作（加待办、记事实），从时间线的轮分组或 `data/trajectory.jsonl` 里取目标轮的 `turn_id`；给 `undo_last` 传 `to` 参数（值为该 `turn_id`），或在调试侧直接调用 `fw.rollback_to(turn_id)`。

**预期现象**

- 单次同类失败只进 `pending`，不生成规则；第 2 条独立事件后才在 `rule` 事件里看到规则族与置信度；置信度按 Beta(1,1) 后验均值计算，连续失败且无成功成效的规则会自动停用；
- 时间线是单文件 HTML：按轮分组、失败高亮、哈希链、深浅色自适应、HTML 转义、无 CDN；撤销账本只显示数量、不显示明细；
- `fw.rollback_to(turn_id)` 从目标轮之后的 `turn_end` 事件逆序取回撤销账本逐轮执行，能把世界回退到指定轮，而不只是撤上一轮；
- 机器对照可跑 `python tools/benchmark.py`（学习前 56.25% → 学习后 81.25%，+25.00 pp，8 条任务被救回，仍保留 6 条硬失败）。原理与代价见 [ADR 0003](adr/0003-preference-and-evolution.md)、[ADR 0004](adr/0004-verifiable-execution.md)。

### 断言 8：工作台能点开、最大化、关闭后回到桌宠

**操作**

1. 右键角色 →「打开工作台（可最大化）」（也可用托盘菜单，或单击角色后点输入条右侧的「工作台」）。
2. 点主区标题栏右侧或左侧底部的「最大化 / 还原」切换；双击窗口标题栏也应能铺满屏幕。
3. 依次点左侧七个页签，在「我的偏好」里应能看到断言 6 学到的偏好；点到最后第二个「网页调试台」时，页面里应出现一个真的网页（顶部大标题「凌零 · 智能体服务」，能滚动、能点），而不是一段叫你去 `pip install PyQtWebEngine` 的说明文字。**这一页底下不再有工作台命令栏**——网页自带输入框，同一屏两个输入框会让人不知道该往哪打字；切回别的页签，命令栏照旧回来。
4. 点最后一项「关于与设置」，在「执行轨迹（工程面板）」卡片上点「打开执行轨迹」：标题应变成「执行轨迹」，而左侧导航**没有任何一项是亮着的**（这一页是给排障和讲实现用的，不占用户界面的导航位）。
5. 在窗口底部全局命令栏（占位「今天帮你做些什么？试试「读一下 D:/资料/报告.pdf」；回车发送」）输入一句话并回车，应交给桌宠执行并自动切到对话页。
6. 工作台默认已是深色风格；可点左侧底部「主题」切到浅色，再点 X 关闭窗口。
7. 再点一次入口打开窗口。

**预期现象**

- 首次打开即为最大化；切换后按钮文字在「⛶ 最大化」和「⛶ 还原」之间变化；
- 顶部有菜单栏（文件 / 编辑 / 窗口 / 帮助 / 关于），左侧导航带品牌、版本与分组计数，底部有全局命令栏（切到「网页调试台」时它会收起，那一页只留网页自己的输入框），整体为深色 WorkBuddy 风格；
- 八个页面都能打开且显示真实数据（偏好条数、规则条数、轨迹轮次都是真实数据；轨迹轮次在「执行轨迹」页里看，窗口最底部不再常驻这些数字，只留一句操作反馈）；其中七个在左侧导航里，**「执行轨迹」只在「关于与设置」里有入口**（工程面板不占用户界面的导航位，进去时导航条没有任何一项高亮）；「网页调试台」页内嵌的就是浏览器打开 `http://127.0.0.1:8000/` 看到的同一份网页，桌面与网页共用同一套会话、授权与视觉；
- 关闭后桌宠与托盘仍在，程序没有退出；重新打开时主题与窗口状态保持；
- 「执行轨迹」页点「生成并打开时间线」会在数据目录写出 `timeline.html` 并在浏览器打开；
- 全局命令栏或对话页发的指令与桌宠输入条走同一条 `Framework.send_command` 链路，气泡回复同步。

### 断言 9：关于页七个开关点了真会翻能力（不是装饰）

**操作**

1. 打开工作台 → 左侧「关于与设置」→ 找「当前开关」卡片：七行，每行右侧是一个带边框的按钮（绿色「开启」/ 红色「关闭」），不是只读文字。
2. 点「契约严格模式」那行的按钮，把它从「关闭」翻成「开启」。
3. 看右下角状态栏，应出现绿色一句：「契约严格模式：已开启（已存盘，下次启动同样）」。
4. 打开 `%APPDATA%\DesktopPet\user_settings.json`，里面应有 `"effect_spec_strict": true`。
5. 切到别的页再切回关于页，按钮仍是「开启」；重启程序后也仍是「开启」。
6. 点「事件轨迹」的按钮把它关掉，随便说一句话，再点「关于与设置」→「打开执行轨迹」回那一页看轮次——不应增加（子系统当场被撤，不需要重启）。
7. 再点一次把它开回来，说一句「记一条待办：验收开关」，轮次应重新开始增加。

**预期现象**

- 七个按钮都有手型光标、悬停变色，点一下状态当场翻转；
- 每次点击都写 `%APPDATA%\DesktopPet\user_settings.json`；写盘失败时按钮弹回原样并如实显示「开关已改但没写进配置文件」，不会假装已存盘；
- 「事件轨迹 / 偏好学习 / 自我进化」关掉后对应子系统对象当场变 `None`（轨迹不再记录、偏好不再学习、规则不再新增），开回来立即恢复，全程不需要重启；
- 反复切页不会攒出重复按钮：关于页始终七行、七个按钮。

### 断言 10：桌面读根外路径要弹授权卡，三个按钮后果不同且重启失效

**操作**

1. 在桌面/文档/下载之外造一个目录 `D:\验收资料`，里面放 `甲.txt`、`乙.txt`。对桌宠说「读一下 D:\验收资料\甲.txt」。
2. 看浮层卡：三个按钮下面各有一行后果说明，右下角是倒计时（默认 120 秒）。点「只读这一个」。
3. 再说「读一下 D:\验收资料\乙.txt」；然后说「再读一次甲.txt」。
4. 打开工作台 →「本机访问」，看授权列表，点「全部撤销」，再读甲.txt。
5. 退出程序并重启，再说「读一下 D:\验收资料\甲.txt」。

**预期现象**

- 第一次弹卡；点「只读这一个」后甲能读；**同目录的乙仍要再弹一次**（安全断言的核心，file 档不溢出到兄弟文件）；再读甲不再弹；
- 「本机访问」里能看到这条是「仅这一个」、路径与放开时间；「全部撤销」后列表清空，再读甲**必须重新弹卡**；
- 重启后再读甲也要重新弹卡——授权不落盘；`.ssh`/`.env`/凭据这类文件点哪个按钮都不读；
- 如果放着卡片不点：120 秒后卡片写「已超时，按拒绝处理」，下一次回复明说「等太久没等到你确认，我按拒绝处理了」，不伪装成用户主动拒绝。

### 断言 11：浏览器和桌宠不分治（杀手级验收）

**操作**

1. 保持桌宠运行，另开一个终端执行 `uvicorn api.server:app --host 127.0.0.1 --port 8000`，浏览器打开 `http://127.0.0.1:8000/`。
2. 在网页调试台点「读本机文件」，填 `D:\验收资料\乙.txt` → 发送。页面出现授权确认条（三个按钮）。
3. 点「允许整个文件夹（本次会话）」。
4. 切回桌宠，说「读一下 D:\验收资料\丙.txt」（先造好这个文件）。
5. 在桌面「本机访问」点「全部撤销」，再让网页读同一个文件。
6. 关掉桌宠，再让网页读一次；如设置了 `LINGLING_API_TOKEN`，不带令牌直接 POST `/grant/{gid}`。
7. 连着让网页读两个不同文件（甲、乙），桌面上会**叠着出现两张授权卡**：先把第一张直接关掉（不点按钮），再在网页确认条上点「允许这一个」；然后让桌宠读第三个文件，读到一半在桌面卡片上点「拒绝」。

**预期现象**

- 网页请求先返回 `pending_grant`（不阻塞等待），确认条出现；点 tree 后桌面侧**不再弹卡**，同目录的丙.txt 直接读——这一条不过就算没做；
- 关掉第一张卡不会把网页上刚点的「允许」改写成「拒绝」：那个文件真的被读了，气泡不会说「你没授权」；
- 两张卡各自对应各自的文件，位置错开都能点到；后一条请求的「拒绝」只丢它自己那一步，不吞掉前一条已经放行的读取；
- 桌面「全部撤销」后网页再读同一路径**重新出现确认条**；撤销是真清空，不是只藏 UI；
- 桌宠关掉后网页端用同一套判据自持，仍可用，但授权只在这个网页服务里有效；
- 配了令牌时 `/grant/{gid}` 不带 `X-API-Key` 返回 403，非法 decision 返回 400；未配令牌时只接受本机回环。设计见 [ADR 0007](adr/0007-cross-end-shared-grant-channel.md)。

### 断言 12：本机访问页看得见、撤得掉，气泡给读取证据

**操作**

1. 说「看看 D:\验收资料 这个文件夹里有什么」，再说「读一下 D:\验收资料\甲.txt 和乙.txt」（多份会走 `paths` 批量入口）。
2. 打开工作台 →「对话」，看助手气泡下面的读取证据卡；再点「关于与设置」→「打开执行轨迹」看事件轮次。
3. 点左侧导航「本机访问」计数入口，看放开列表、支持格式与读取证据；点「我的交付」核对有没有读取记录。
4. 在深浅两套主题下重复第 2、3 步。

**预期现象**

- 证据卡写明「列了几项 / 读了几页 / 跳过什么 / 截到多少字」，批量读会写「批量共 N 份，实读 M 份、每份最多 600 字」，只说一句「读完了」不算通过；
- 支持格式文案与 `framework/path_guard.describe_formats()` 生成的一致，界面、提示词、文档里没有另一份硬编码清单；
- 左侧导航的「本机访问」计数与放开条数一致，点它直达该页；空态写「当前只放开默认目录（桌面 / 文档 / 下载）」，不是留白；
- 读文件**不进「我的交付」**（没有产出文件），读取记录只在「本机访问」页；
- 深浅主题下新页面、授权卡、证据卡的文字都不裁切。设计见 [ADR 0008](adr/0008-restorable-write-actions.md)。

### 断言 13：偏好默认不展示，打开开关才看得见；模型层只收有原话证据的

**操作**

1. 打开工作台 →「我的偏好」：默认应只有一句说明，看不到表格和删除按钮。
2. 去「关于与设置」，把「在界面上显示偏好」打开，再切回「我的偏好」：表格出现，六列（偏好 / 当前值 / 来源 / 置信度 / 命中 / 证据数）。
3. 说一句「以后 PPT 都用深色」→ 表格应出现 `doc_theme`，来源写「规则命中」。
4. 配了 API Key 时，再说几句带长期偏好的话（如「我是做财务的，以后别跟我讲实现细节」），累计到第 3 轮后，表格应多出一条开放式偏好，来源写「模型归纳」，置信度 0.72。
5. 打开 `%APPDATA%\DesktopPet\preferences.json`：只有命中短语与原话哈希，没有原话明文。

**预期现象**

- 默认状态（`preference_panel=false`）下界面看不到任何偏好明细，但**偏好仍在学、仍在影响回复**——关掉的只是展示，不是学习；
- 打开开关当场显示、不用重启；再关掉又恢复成说明文字；
- 模型抽取的每条都必须带原话引用；编造的（查无实据、少于 4 字）被丢弃，不写进文件；
- 没配 API Key 时「偏好自动归纳」即使开着也不发请求、不报错，只是不产出模型层偏好；
- 规则层与模型层写同一个文件，同一维度只留一条，来源以先写者为准。

### 断言 14：本地微调模型接进主链路；不可用时如实降级

**操作**

1. 装可选依赖并训出适配器：`pip install -r requirements-finetune.txt` → `python finetune/train_lora.py`（产物落在 `finetune/output`，不入库）。
2. 打开托盘菜单「显示设置」，找到「本地微调模型（LoRA，选填）」：勾上「使用本地微调模型」，把「适配器」填成 `finetune/output`，点「测试加载」。
3. 看状态文字：加载成功会写「✓ 加载成功（xx.x 秒）· 基座模型名」；没装依赖会写清楚缺哪个包，没训过适配器会写清楚适配器路径不对——**不会假装成功**。
4. 对着桌宠说一句话（例：「帮我打开微信」）：开了本地微调后这句话先问本地模型。
5. 关掉开关再说同一句：这次走云端模型（或离线规则）。

**预期现象**

- 开关、基座、适配器路径、设备四项都写进 `%APPDATA%\DesktopPet\user_settings.json`，重启程序后还是同样的值；
- 本地模型答得不合动作协议时，这一句会退回云端回答（用户看不出切换，只看到正常回复）；
- 没装 `requirements-finetune.txt` 的机器照常启动、照常用云端模型，本地通路只在开关打开时才被问到，且不拖慢主链路；
- 训练与产品推理用同一份提示词模板（`framework/lora_format.py`），模板改一处两边一起改。设计见 [ADR 0010](adr/0010-lora-as-main-chain-provider.md)。
