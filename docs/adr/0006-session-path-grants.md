# 0006 · 会话内路径授权与统一文件读取层

- 状态：已采纳（2026-11-17）
- 相关：`framework/path_guard.py`、`framework/grants.py`、`framework/file_reader.py`、[ADR 0004](0004-verifiable-execution.md)

## 背景

`read_doc` / `analyze_data` 的 `path` 完全由大模型输出决定，读到的正文会进【检索资料】缓冲并随下一轮请求发给第三方 LLM。`path_guard` 最早是**默认拒绝的两态判定**：不在几个根目录里就直接拒。这条边界挡住了 `.ssh` 私钥、`.env`、浏览器凭据，也一并挡住了用户自己放在 `D:\`、`E:\` 里的资料——「读任意路径」这个需求等于被安全默认值判了死刑。

同时，"能不能读"的判据散在三处：`path_guard` 的后缀表、`core._do_read_doc` 里的 if/elif、提示词与气泡里的「目前支持 txt/md/csv/json/docx/pptx/xlsx」。加一种格式要改四处，漏一处的结果就是**文案说有、实际读不了**（这次就是：PDF、代码文件、压缩包、目录本身都已经或即将能读，文案还停在 6 种）。

## 决策

### 1. 判定改成三态：`allow` / `grant` / `deny`

`check_read(raw, grants=None) -> (verdict, path, reason)`。

- `allow`：静态白名单根内，或已被本次会话授权记录覆盖 → 直接读；
- `grant`：**格式认得、不是敏感项，但不在根内** → 这不是失败，是一次待确认请求，界面拿去问用户；
- `deny`：终态。路径为空 / 不存在 / 格式不在表里 / 超过 20 MB / **命中敏感表**。

老接口 `validate_read_path()` 原样保留，但语义收窄为「只认静态白名单」：`grant` 也返回 `ok=False`。网页入库、单测这类**不会弹确认**的调用方继续用它，不会因为引入了授权就默认放行。

**为什么非要多出一态**：两态下「放开任意路径」只有一条路——把 `allowed_roots` 改成不设限，那等于拆掉边界。三态把"要不要放开"这个决定从开发者手里交给用户、并且限定在这次运行里。

### 2. 敏感判定优先，且永远不被授权覆盖

`check_read` 的顺序是固定的：存在性 → `is_sensitive()` → 格式表 → 大小 → 根目录 → 授权记录。顺序写反一步，「允许整个文件夹」就变成「允许整个文件夹里的 `user_settings.json`」（那个文件里存着 API Key）。所以顺序由契约 `敏感判定先于白名单与授权` 钉住，不是靠注释提醒。

顺带修掉一个真实漏洞：`is_sensitive` 原先只检查 `parts[:-1]`，于是**目录名本身**是 `.ssh` 时不算敏感，列一层目录就能把私钥文件名与大小抄走。现在检查全部分段。

### 3. 授权只有两档，且只活在进程里

- `file`：只放开这一个路径（目录则只允许列它这一层）；
- `tree`：放开这个目录及其整棵子树——用户说的「是否允许完全访问」就是这一档。

两档都**不落盘**，重启回到默认拒绝。理由有三条，缺一条这个决定就不成立：

1. 配置文件 `%APPDATA%\DesktopPet\user_settings.json` 自己就在敏感名单里、也在白名单根之下。把授权写进它，等于「用一份可以被 `read_doc` 读走的文件，保存能不能读走文件的通行证」；
2. 「上次给过」不等于「这次还要给」：一次临时的解压目录授权，永久留着就是长期敞口；
3. 不落盘才敢把授权记录暴露在 UI 里（工作台能看到"这次放开了哪些"），用户随时能一眼看完。

`GrantStore` 有单测用 AST 检查它只 import `os`、不含 `open(`——**"不落盘"是模块级不变量，不是靠人记得**。

包含判定按路径段（`is_within(child, parent)`，比对 `parent.rstrip(sep) + sep`），不用字符串 `startswith`：后者会把 `D:\foo2` 判进 `D:\foo` 的子树，那是越权。归一化用 `normcase(realpath(abspath(...)))`，Windows 上大小写与正反斜杠换写法不会要求用户点两次。

### 4. 判据与读取层只依赖标准库，桌面与网页共用一份

`path_guard` / `grants` / `file_reader` 顶层只 import 标准库（重依赖 `pypdf` / `openpyxl` / `win32com` 一律在函数内懒加载），这条也是契约。因为**授权确认有两条 UI 路径**：桌面的浮层卡片和网页调试台的确认条。判据层一旦拖上 Qt，网页端就只能在自己的进程里重写一遍判定——那就是分治的开始，而分治正是这个项目前面几处「文案说有、按钮是摆设」的病根。

`Framework.ask_grant` / `answer_grant` 是唯一入口（F2/F3 接），两端只是把同一个 verdict 渲染成不同控件。

### 5. 统一读取层：一张格式表 + 两个诚实约定

`file_reader.read(path, kind="")` 按 `kind_of()` 分派到 `list_dir` / `read_text` / `read_archive` / `read_pdf` / `read_office` / `read_legacy_office`，返回统一形状 `{ok, kind, text, note}`：

- **永不抛异常**：损坏、加密、文件被占用、缺依赖，都在最外层变成 `ok=False` + 中文短句；
- **不许空手报成功**：`ok=True` 但 `text` 是空的，一律改判 `ok=False`（唯一例外是空目录——"这个文件夹是空的"是真实答案）。否则调用方会念「读完了」而资料缓冲里什么都没有；
- 截断、跳过、只读了前 N 页、只列了前 N 项，**必须写进 `note`**，用户看到的和实际读进上下文的一致。

能力文案从表生成：`path_guard.describe_formats()` 与 `advertised_exts()`，契约检查「文案里列出的每个后缀都在判据表里」。这样加格式只改一张表，提示词、气泡、文档三处不会再各说各话。

**明确不属于这一层的**：图片与扫描型 PDF。图片是视觉动作的活；扫描件抽不出文字层时，`read_pdf` 返回 `没有文字层（扫描件/图片型 PDF）…要读得走视觉模型`，而不是硬解或静默返回空串。

### 6. 压缩包只在内存里读

条目名先归一化，`..` 与绝对路径成员直接跳过（zip slip）；成员再过一次 `is_sensitive` 与二进制后缀表；**不落地解包**，只 `read()` 进内存，所以不存在写越界。默认最多顺带读 12 个文本成员、每个截到 1500 字，其余只列名——不然一个 `node_modules.zip` 能把上下文吃满。

## 代价与边界

- 用户会**被问一次**：`grant` 不是错误，但比老版本的"直接拒"多一次点击。这是放开任意路径的必要代价，也是唯一能把"要不要放开"交给用户的时机。
- `tree` 档一旦点上，整棵子树在本次运行内都可读。所以确认卡片必须把目录名本身显示清楚，且敏感项已经在上游被永久排除。
- 老格式 `.doc/.xls` 依赖本机装了 WPS/Office：没装就如实说转不出来，请用户另存新格式。这条能力不做成"看起来支持"。
- 这一层交付后**桌面上还点不到**：F2 才把它接进动作循环（暂停/续跑），F3 才让网页端共用同一条确认通道。F1 的可验收口径是机器对照，见下。

## 怎么验（机器对照）

```
python -m pytest tests/test_path_guard.py tests/test_grants.py tests/test_file_reader.py -q
python tools/check_contracts.py
```

覆盖到的失败类别（不是喂理想数据）：`..` 逃逸不继承根内放行、指向根外的符号链接、兄弟目录蹭子树、`file` 档顺手放开父目录、给了整树仍然读不到 `.ssh`、`.exe/.png` 终态拒、后缀写着 `.txt` 内容却是二进制、GBK 与 BOM、超长截断、空文件、损坏压缩包、zip 内 `../` 与密钥成员、真造一份有文字层的 PDF 读出正文 / 再造一份无文字层的如实说扫描件、缺 `pypdf` / 缺 `pywin32` 的降级、`.ppt` 在起 COM 进程之前就拒绝。
